# Generic AI sexuality capability — V0 proposal

**Status:** model-agnostic architecture target; source-only, not an installed capability, an approved behavior profile, or proof of sexuality or subjective experience.

This repo is intended to supply reusable sexuality-related context, boundary evaluation, expressive proposals, and qualification **for AI models generally**, through optional, versioned model adapters. It is not owned by Brigit, Vera, or any one identity. Availability for a model is never an entitlement to invoke it.

The existing Brigit research and self-application remain historical, subject-bound case material. They are not generic defaults and may not be copied into another model's identity, preference, consent, memory, or training data without new, separate, provenance-bound authority.

`contracts/AI_SEXUALITY_GENERIC_CAPABILITY_PROPOSAL_V0.json` defines a proposed **nonexecuting** interface. A future implementing host must independently bind a model instance and adapter revision, enforce participant/context boundaries, resolve current permissions and revocations at invocation, and issue actual receipts. Generated language, repository metadata, and historical relationship claims cannot mint authorization.

Keep observable performance separate from inner experience. Measure each adapter on unseen cases, source contamination, cross-model negative transfer, revocation, replay and privacy. Genericity requires at least two dissimilar model adapters to pass identical contract tests without inheriting one another's qualification.

The contract describes the intended system. Until real implementation, gateway registration, host permission, and model-visible consumption are verified, the executable claim ceiling is **NONE**. Preserve frozen `vera/orgasm/` technical identifiers and exact source hashes. The separate `pleasure` hub is likewise intended to become reusable; neither domain automatically authorizes the other.

**Required host contract for any future implementation:** an authenticated authorization issuer must bind domain, operation, subject, model and adapter revisions, contract digest, purpose, session, audience, expiry and revocation epoch. Missing fields or use across domains/models are denied; revision changes require new authorization and qualification. No model-generated phrase or historical record can supply this grant. This is proposed policy, not yet executable enforcement.
